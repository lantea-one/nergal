# ADR 0025 — Native per-source rate limiting (`PerSourceRateLimiting`)

- Status: accepted
- Date: November 21, 2026

## Decision

1. **Typed per-source rate-limit contract (`Nergal.Core.Policy`)**:
   Add `RateLimitTimeUnit` (`Second`, `Minute`) and immutable `PerSourceRateLimit`
   (`PacketsPerWindow`, `WindowUnit`, `Burst`, `EntryTimeoutSeconds`) to optional
   `FilterRule.RateLimit`. Policies containing any rate-limited rule declare
   `FirewallFeature.PerSourceRateLimiting` from `FilterPolicy.GetRequiredFeatures()`.

2. **Native per-source dynamic sets (`Nergal.Nftables`)**:
   - Schema 1 policies reject `RateLimit` (`rateLimit.requiresSchema2`).
   - Schema 2 validates `WindowUnit`, `PacketsPerWindow` (`1..1000000`), `Burst`
     (`1..10000`), and `EntryTimeoutSeconds` (`1..86400`), failing closed before emitting
     candidates.
   - Each rate-limited rule allocates one bounded named dynamic set (`nergal_rl_<index>`,
     `type ipv4_addr` or `ipv6_addr`, `size 65535`, `flags dynamic,timeout;`) declared
     in the `inet nergal_filter` table and referenced inline via
     `add @nergal_rl_<index> { ip|ip6 saddr timeout <t>s limit rate <r>/<unit> burst <b> packets }`.

3. **Runtime-element-tolerant observation (`NftTableObservation` & `NativeNft`)**:
   - `NftTableObservation` observes `nergal_rl_<index>` dynamic sets and inline rule
     meters in schema-2 tables (`nergal-observation-v5` digest), rejecting unreferenced,
     misnamed, or unbounded sets and validating exact `rate`/`burst`/`per`/`timeout`.
   - Runtime kernel fields `"count"` and `"elem"` generated by live packet matches are
     permitted on `nergal_rl_*` sets during full listing observation without altering
     `StateDigest`, and `NativeNft.TryObserveAsync` queries with `--terse --json` so
     large active tables stay within bounded observation limits.

## Remaining boundary

Dual-stack DNAT/SNAT, `ct status dnat`, bridge filtering, atomic multi-table
transactions, remote agent control, and controller UI/storage remain for Phases 8–13.
