# ADR 0005: independent watchdog in an isolated conformance fixture

- Status: accepted
- Date: November 18, 2026

## Decision and boundary

Implement a test-only .NET watchdog/worker executable under tests/integration,
using the local journal and compiler. It refuses ordinary-host execution: the
wrapper must create fresh user and network namespaces, the executable checks both
against caller namespace identities and requires namespace-local root mapped to
one non-root host UID. This guard prevents accidental launches; it is not an
adversarial authorization boundary or a production sandbox policy.

The fixture owns its fresh namespace and only a fixed inet nergal_filter table.
It accepts no arbitrary policy, command, nft fragment, socket or agent endpoint.
Its only artifacts are compiler-generated empty input policies with explicit accept
or drop defaults. Stored artifacts must exactly match those generated bytes before
execution. Native process arguments are fixed, nft input uses stdin without a shell,
and a strict structured table observation rejects unexpected objects/properties.
Foreign sentinel tables must remain unchanged. Web and production code gain no
firewall executor, production enrollment or replacement API.

## Ordering and recovery tested here

A private per-resource process lock serializes kernel side effects, worker decisions,
confirmation and watchdog restoration. It is released by the OS on process death.
SQLite write transactions serialize journal decisions; the clock is sampled after
its transaction lock is acquired. The watchdog runs as a separate process, durably
acknowledges arming before the worker may apply, and retains the original boot-scoped
deadline on restart. Polling cannot renew a lease.

The worker checks the deadline under the execution lock, verifies the exact fixture
baseline shape, validates the complete replacement batch with nft --check, applies
one native transaction and only then acknowledges apply success. Timeout first commits
RollbackRequired; confirmation can no longer win. The watchdog then checks live state,
restores only its exact known baseline with native check and atomic apply, verifies it,
and acknowledges restoration. A failed observation/restore records RecoveryRequired
and never releases the reservation. Confirmation verifies candidate state and commits
the terminal event/revision together; no old watchdog may restore confirmed state.

The fixture-only replacement transaction deletes the known table and recreates it
inside one batch. The production compiler remains create-only under ADR 0002. The
fixture's fresh-namespace ownership must not be generalized to existing host tables.

Kill points deliberately hold the execution lock after apply/before acknowledgment,
and after restore/before acknowledgment. On watchdog restart, a live exact baseline
can be acknowledged as restored, while an exact candidate is restored at the original
deadline. Anything else blocks recovery. Boot mismatch remains fail-closed. There is
no general cross-reboot recovery, production daemon supervisor or host privilege model.

## Evidence and remaining work

Tests use real processes, SIGKILL, native nftables transactions and real IPv4/IPv6
TCP/UDP packet outcomes. They cover worker death before/after apply, watchdog restart,
restoration-before-ack death, timely confirmation, stale/late confirmation, foreign
object rejection and corrupt/missing journal denial. These are fixture guarantees,
not claims of production-ready enrollment, arbitrary owned-state restoration, device
power-loss safety, service supervision, OIDC or authenticated agent transport.
